= Prometheus metrics scraping methods

[role="_abstract"]
Get real-time, aggregated visibility into the health, performance, and resource usage of your {mcpg}. Prometheus metrics give you a high-level numerical overview of your system state over time.

* Use internal cluster scraping for ad-doc debugging and verification. Retrieve metrics through pod IP discovery.
* Use Kubernetes pod service discovery for continuous scraping with Prometheus.
* If you use Prometheus Operator, configure an equivalent pod-IP scrape job in the operator-managed Prometheus instance.

.Prerequisites

* You installed and configured Prometheus or the Prometheus Operator.

.Procedure

. Optional. To manually verify that the metrics endpoint is responding locally before configuring Prometheus, run the following command to forward the port and inspect the payload:
+
[source,terminal,subs="+quotes"]
----
POD=$(oc get pod -n _<mcp_gateway_namespace>_ -l app.kubernetes.io/name=mcp-gateway \
  -o jsonpath='{.items[0].metadata.name}')
oc port-forward -n _<mcp_gateway_namespace>_ pod/$POD 9090:9090 &
sleep 1
curl http://localhost:9090/metrics
----
+
* Replace `_<mcp_gateway_namespace>_` with the namespace where your {mcpg} pods are running.
+
[NOTE]
====
This command is for local manual inspection only.
====

. Configure Prometheus to scrape the pod-local endpoint directly. Use the following pod service discovery configuration:
+
[source,yaml,subs="+quotes"]
----
scrape_configs:
  - job_name: mcp-broker
    kubernetes_sd_configs:
      - role: pod
        namespaces:
          names: ["_<mcp_gateway_namespace>_"]
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_label_app_kubernetes_io_name]
        action: keep
        regex: mcp-gateway
      - source_labels: [__meta_kubernetes_pod_ip]
        target_label: __address__
        replacement: $1:9090
----
+
* Replace `_<mcp_gateway_namespace>_` with the namespace where your {mcpg} pods are running.
* Add the scrape job to your Prometheus configuration.
* User workload monitoring must be enabled when you use the OpenShift user-workload Prometheus instance. Ensure that you set `enableUserWorkload: true` in the `cluster-monitoring-config` ConfigMap in `openshift-monitoring`.
+
The generated broker `Service` exposes the HTTP and gRPC ports but not port `9090`, so scrape the pod-local endpoint directly. The default generated broker container does not declare a named `metrics` port. A `PodMonitor` with `port: metrics` works only when your deployment exposes port `9090` with that name.
